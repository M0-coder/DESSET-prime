# DESSET Prime V4.4 — arquitectura de confianza

**Estado:** candidata para revisión de diseño y mensaje, NO publicación.  
**Alcance:** `M0-coder/DESSET-prime`, rama `design/v4-kinetic-identity-no-deploy`, PR #1 borrador, sin merge, DNS, Cloudflare ni release.  
**Doctrina:** Primero fija el alcance: arquitectura, compilación, pruebas unitarias e instrumentadas, cobertura, análisis estático, calidad de CI, seguridad, reproducibilidad, mutation testing, deuda técnica y evidencia de ejecución.

## Criterio de diseño

**La confianza requiere respaldo.** Una marca sólida no debe fingir que existe una empresa formalmente registrada, una aplicación habilitada o clientes activos. Tampoco debe debilitarse repitiendo que "solo propone". Esta versión establece una identidad y dirección fuertes, pero distingue el **primer foco de negocio**, la **etapa de desarrollo** y la **disponibilidad efectiva**. No incorpora logotipos fabricados ni medallas de verificación.

### Cambios verificables del código
- **H1 original:** `EL COMERCIO SE MUEVE`, intacto. La descripción pasa a `En DESSET estamos construyendo un sistema para conectar pedidos, comercios y entregas`; no afirma que se puedan contratar.

- **Comercios:** conecta el propósito con la escucha y definición de necesidades reales; no habla de ganancias, reparto disponible o resultados hipotéticos.

- **Marca:** el símbolo histórico PNG y el SVG de arquitectura permanecen sin alteraciones. La comparación canónica con Figma sigue pendiente.

## Pruebas
- Unitarias/contrato: tres estados exactos, un solo CTA principal, ausencia de garantías/certificados simulados, contenido informativo y límites de CSS.
- Instrumentadas: Chrome headless a 1440, 1024, 768, 390 y 320 px y preferencia de movimiento reducido; verificar geometría de los tres estados, 3 columnas en escritorio y 1 en móvil, fuentes legibles, cero overflow y capturas del panel.
- Compilación: estáticos HTML y CSS; `node --check` para scripts JS. 
- Cobertura: no existe porcentaje de coverage certificado. 
- Análisis estático: fuentes, enlaces, CSP y reglas estructurales; SAST general no implementado. 
- Seguridad: cabeceras `_headers` aún no verificadas sobre un servidor desplegado. 
- Reproducibilidad: la evidencia debe ligarse al SHA probado y al run exacto. 
- Mutation testing: no hay score completo; no atribuir garantías inexistentes.
- Deuda: CSS de legado y proceso de revisión de marca; no comprometer más movimiento ni pantallas para generar apariencia de credibilidad.

## Restricciones antes de autorizar salida pública
1. Verificar identidad, tipografía, logo y derechos en el Figma canónico. La conexión anterior superó el límite Starter y **no** realizó comprobación visual definitiva.
2. Verificar quién administra y responde los perfiles enlazados; establecer canal empresarial controlado, con reglas de privacidad. **La web no debe vender conversación inmediata si no existe capacidad de respuesta.**
3. Completar documentación de constitución y representación comercial aplicable en Perú. Evitar afirmar registro, RUC, licencias o socios sin documentos.
4. Pruebas con lectores de pantalla, zoom 200–400 %, móviles reales y Core Web Vitals, verificar headers HTTP al servir assets y hacer revisión manual de seguridad.
5. Proteger la rama `main`, fijar estrategia de integración del PR (actualmente apunta a V3), documentar rollback y autorizar por SHA.
6. Evaluar el texto con 3–5 comercios reales; medir si entienden el servicio y pueden encontrar cómo acercarse. **No atribuir mejora de conversión sin datos.**

**GO técnico de preview ≠ GO legal/comercial ≠ autorización de merge/despliegue.** La web oficial `desset.lat` y `M0-coder/DESSET` quedan inalterados.
