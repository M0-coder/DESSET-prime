# DESSET Prime V6.9 — Presentación institucional permanente

**Ámbito:** únicamente `M0-coder/DESSET-prime`, PR #2 en borrador. NO MERGE, NO DEPLOY, NO RELEASE, NO DNS y no modificar `M0-coder/DESSET`.

## Principio decisivo

DESSET es una **marca empresarial de servicios de comercio, tecnología y logística**. La web debe transmitir identidad empresarial y explicar el funcionamiento del ecosistema, no parecer la solicitud de financiación de una startup. La web **no** es un sistema de pedidos, pagos o ventas. Tampoco se puede afirmar que ya se realizan entregas si aún no están activas.

**Separación de conceptos:**
1. **Presentación permanente:** identidad de marca, tres pilares, catálogo institucional, explicación Elegir / Preparar / Entregar, públicos, funciones, escenas gráficas, canales.
2. **Disponibilidad operativa variable:** los accesos reales a las aplicaciones y servicios comerciales se validan independientemente. Una página de marketing puede permanecer idéntica antes y después de lanzar, sin prometer prestaciones inexistentes.
3. **Canales publicados:** se conservan exactamente los tres perfiles que figuran en el HTML, marcados `data-channel-review="pending"`; su titularidad y acceso deben confirmarse antes de presentarlos como verificados. No inventar teléfonos, correos, dominios secundarios o cuentas.

## Implementación ejecutada

- Se eliminan del mensaje principal frases repetitivas como «somos un proyecto», «estamos construyendo», «antes del lanzamiento», «en construcción», «Horizonte futuro» y referencias reiteradas a la fase de validación.
- Nuevo texto institucional en el hero, pilares de confianza **Comercio conectado / Logística de última milla / Tecnología DESSET** y presentación de servicios sin promesas de operación real.
- Navegación de marca: **Servicios / Cómo funciona / Canales DESSET**. Se mantienen seis secciones, IDs, accesibilidad, arte y layout, WebP premium y Three.js opt-in.
- El proceso **Elegir → Preparar → Entregar** se explica como arquitectura de servicio, no como simulación de entregas reales. En la escena 3D el aviso conceptual se conserva porque es una representación artística.
- Las aplicaciones DESSET tienen un módulo permanente dentro de la sección de servicios; en el estado actual solo informa **«Acceso público no habilitado»**. Ese estado único reemplaza múltiples avisos repetidos por toda la web.
- `scripts/service-state.js` mantiene `applicationDistribution:"not_published"` y listados Android/iOS `verified:false` y `url:null`. Sin enlaces de descarga inventados.
- Para habilitar una descarga, son obligatorios **dos controles simultáneos**: estado `published` explícito y URL `https` oficial en los hosts de Google Play o App Store, identificada como verificada. Cambiar una bandera o escribir una URL arbitraria no activa el botón.
- Cambiar la disponibilidad de la aplicación **no** equivale a habilitar ventas, pedidos o repartos: las operaciones comerciales tienen sus propios gates y autorizaciones.
- No se realiza petición de red, seguimiento analítico ni almacenamiento local desde el controlador de disponibilidad. La web mantiene Content Security Policy, `noindex,nofollow` y `form-action 'none'`.

## Estilo y coherencia

- El sistema visual 60-30-10 existente permanece; el nuevo módulo usa el mismo blanco cálido, azul institucional y radios de 12/18 px.
- No se crean una nueva portada, nuevos modelos 3D ni una sección de venta. Se reduce el retrabajo futuro.
- El aviso de no disponibilidad queda pequeño, claro y verificable; no se esconde ni se repite en cada tarjeta.
- El pie y la zona de contacto recuerdan que pedidos y pagos pertenecen a las aplicaciones, **nunca a esta web**.

Primero se fija el alcance: arquitectura, compilación, pruebas unitarias e instrumentadas, cobertura, análisis estático, calidad de CI, seguridad, reproducibilidad, mutation testing, deuda técnica y evidencia de ejecución.

Verificar sobre el mismo SHA:
- Contratos de HTML, seis secciones, idioma español, jerarquía 60-30-10, URLs externas y noindex.
- Unitarias del controlador: fase inactiva, bandera `published` sin URLs, URL maliciosa, listing oficial verificado y ausencia de solicitudes de red.
- CI del sitio empaquetado `dist/` con SHA-256 para cada archivo; allowlist de JS local, sin publicación.
- Chrome y responsive: identidad permanente visible, estado `not-published`, sin enlaces de tiendas reales en defecto, navegación accesible a 320/390, modelo GLB y escena sin regresiones.
- Pruebas GPU WebGL2 sobre fuente y `dist/` sin confundir SwiftShader con GPU física; Lighthouse sintético sobre `dist/`.
- Cuatro mutaciones dirigidas y cobertura Node informadas como tales, no como mutation testing integral.
