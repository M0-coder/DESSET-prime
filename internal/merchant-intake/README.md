# Merchant intake — private synthetic integration only

The existing SQLite intake remains the single local persistence layer. Its transaction creates the request, normalized business identity and notification outbox atomically. Replayed keys return the original reference; a changed payload with the same key or the same normalized business name/location with a different key is rejected. This does not resolve aliases, spelling variants or legitimate distinct businesses sharing a name/address; commercial review is still required. Observations are optional and escaped in the reviewer panel. Existing local records are backfilled transactionally; conflicting identities fail closed.

`server.mjs` exports a loopback-only synthetic HTTP server. It accepts intake only when explicitly enabled and only with reserved .invalid email, synthetic name prefix and fixed test telephone. No public website integration, production start command, live email, secrets or deployment. Use `makeReviewerCredential` with a randomly generated test password; only salted scrypt hash is passed to the server. Reviewer identity is assigned by the server, not the caller. Session cookie is HttpOnly/SameSite=Strict, expiring, and revoked on logout/restart; CSRF and exact Origin/Host guards apply to writes. HTTP loopback is not production TLS. Admin panel supports list/details, paging, review, audit history and notification state. All responses are no-store; user text is escaped; no raw errors or applicant payloads are logged by the server.

`notifications.mjs` claims a persistent outbox lease and provides a stable idempotency key. Failed deliveries get a durable exponential retry delay (capped at one hour), permitting other requests to proceed while a retry is deferred. The durable synthetic sink stores only the reference, not personal fields. It simulates provider acceptance, not email delivery. A real provider must honor the idempotency contract across retries and uncertain acknowledgements. There is no scheduled worker or external provider configured. Legacy direct recordNotificationAttempt is retained for existing reference tests only; use lease API for the new worker and do not mix these paths.

Run: `node --test tests/merchant-intake.test.mjs tests/merchant-private-e2e.test.mjs` (Node 22.16.0). Existing CI discovers both tests. SQLite files must be outside repository and public web root. All test data and databases are temporary. Closed-database backup restore is tested, not live backup operations.

Production remains NO-GO: choose and approve durable hosting/storage, verified administrative identity with MFA, HTTPS, distributed rate limits/anti-bot, secure cookies, secrets, observability without PII, monitored scheduled worker with dead-letter handling and alerting and provider idempotency, verified recipient, legal controller/approved privacy policy, retention/deletion/rights and backup/restore drills. Assess duplicate adjudication and perform security review and browser acceptance before activation. No real data until explicit authorization. Approval of request never means merchant activation.
