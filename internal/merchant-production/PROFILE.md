# Merchant profile and commercial follow-up
The existing admin receives contact outcomes, prepares the initial establishment profile, uploads private raster media, records product category/name/description/price in PEN cents, logo if available, and opening/closing times by weekday. Empty hours mean closed; overnight supported; split shifts and temporary schedules belong to the operations app, not this initial profile. An empty catalog cannot be approved. A human representative shares the exact preview with the merchant and records the evidence reference for its approval or requested corrections. This is administrative recording of external conformity, not a merchant-authenticated electronic signature. Any profile edit invalidates the prior version's approval; production readiness requires contact and current approved version. No dummy products, images or commercial examples in production. R2 media validation checks format signature and integrity, not malware or full image decoding. Real R2/Access and live end-to-end tests remain required. RPC getMerchantProfile/getMerchantMedia expose only the approved current profile and its referenced media to the explicitly bound app; getMerchantStatus controls actual eligibility. No new public route or application development. The v7 migration is not deployed. All sample data remains in tests.
