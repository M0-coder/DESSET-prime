# Contract for DESSET applications — v1
Internal function merchantAccountSnapshot(env, merchantId) returns null or {schemaVersion:1,merchantId,status,version,enabled,currency,commissionBps,serviceMinutes,termsVersion}. No PII, no public route. Applications must use a separately authenticated service binding or adapter and treat missing, stale or non-ACTIVE accounts as disabled. Version is monotonic for account lifecycle, not a configuration update version. Integration tests against actual apps are intentionally outside this web onboarding scope. Operational policy: no activation until contract/identity/payout checks, provisioning interface and production approvals are verified. No app implementation here.
Document workflow: upload PDF to environment-specific private R2 binding; quarantine by default; hash and size verified on retrieval; operator scans in approved security tooling and verifies legal evidence before marking verified. Uploading a signed PDF does not execute or validate a legal signature. No automated signature provider or remote malware scanning is claimed. Configuration stores only payout verification reference, not bank credentials. RUC checksum is syntactic, SUNAT verification remains a real operational requirement. Commission cap 1350 bps per previously established commercial policy; legal/tax terms still need owner review. Production onboarding requires real verified records instead of synthetic evidence strings. R2, Access, privacy and legal policy not provisioned; no production release.
