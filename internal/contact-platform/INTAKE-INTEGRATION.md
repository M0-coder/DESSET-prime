# CONTACT-INTEGRATION-02A — intake candidate (NO DEPLOY)
This isolated module implements a submission attempt contract, not a public form or production adapter. It has no global fetch, DOM, storage or service bindings. The existing demo, CI bridge, public pages, Worker default export and deployment contract stay unchanged. The caller supplies an explicitly reviewed transport and a fresh challenge per submission; a new attempt must be created intentionally if content changes. A successful receipt requires the exact API contract (201/new, 200/replay, valid UUID). Ambiguous responses are retryable with the same key; conflicts and invalid submissions are terminal. No automatic retries, no logging of payload or persistence. The UI must preserve an ambiguous attempt until the user explicitly resolves it, handle page lifecycle, challenge renewal and accessibility, and must not enable any real intake before approval. Real privacy/version, Turnstile, rate limiting, origin, timeout, staging, identity and panel integration are still pending. Tests use synthetic data and injected responses. No new dependencies or public files.
